# LiveContainer App Group transfer — 16 October 2026

## Reproduction and upstream findings

The user's Spotify screenshot confirms the new guided flow reached its compatibility check and failed because `installedRecord` rejected every nonempty App Group entitlement. This was an explicit unsupported-feature gate, not an unconnected Create IPA button. The user requested App Group support.

Inspect the official LiveContainer repository rather than the older archived namespace. The installed version shown earlier was 3.8.0. Its [file-manager hook](https://github.com/LiveContainer/LiveContainer/blob/3.8.0/LiveContainer/Tweaks/NSFileManager%2BGuestHooks.m) uses `HOME/LCAppGroup/<original group identifier>` when the selected container's Isolate App Group option is enabled. Without isolation, group storage can live in LiveContainer's private/shared storage outside the granted guest data folder. Its [preferences hook](https://github.com/LiveContainer/LiveContainer/blob/3.8.0/LiveContainer/Tweaks/NSUserDefaults.m) redirects non-Apple preference domains to the guest home, regardless of the original shared container path. Copying group directories alone would therefore miss shared settings.

## Implementation and data flow

Keep the five-page flow. Remove the blanket group rejection, retain group-name validation and the protected-app/version/source checks, and let IPA creation proceed. The helper-staging integration now requests the target's original main-app group entitlements instead of clearing them; it still avoids adding the unrelated synthetic SideStore backup group. Store only the requested original group identifiers in helper metadata, then resolve them against its actual signed `Bundle.main.appGroups`. Accept an exact entitlement or one unambiguous ten-character signing-team suffix; fail for missing/ambiguous mappings rather than enumerate other groups or guess container paths. The existing signer still performs provisioning.

Resolve each granted container through `FileManager.containerURL`. Pass the resulting URL dictionary into the existing detached transfer engine. SideKick itself never gains arbitrary sandbox access. These are the main app's groups; extension-only services, widgets and Keychain migration remain outside this file-transfer feature. Signing configurations that adjust a group to a different unrelated identifier fail clearly until an explicit verified mapping can be supplied.

Schema 2 exports retain Documents and Library, plus `LCAppGroup/<original identifier>` and a bounded group/preference mapping in SideKickTransfer.json. Schema 1 exports remain readable for apps without groups. Copy shared preference plists into the exported main Library/Preferences as required by LiveContainer's hook, preserving mappings for restoration (including a group's own suite domain if it is created later). Conflicting same-name files abort export instead of silently overwriting settings. Unrelated new preference domains that cannot be mapped to a known group are not guessed.

On restore, check app/version/build and the complete expected group set before modifying anything. Stage app trees and all group trees first. Copy the guest's mapped current preference files back into the group staging area, including deletions. Replace user-owned group contents inside the granted container; never rename/delete an OS group-container root or replace its `.com.apple.mobile_container_manager.metadata.plist`. Preserve earlier SideKick recovery generations. Track replacements across all app/group trees and roll them back in reverse order if a move fails; preserve original recovery data if rollback itself fails. Symlinks, nested/aliased roots, malformed identifiers/manifests and inaccessible groups fail before replacement.

The manifest also distinguishes preference files already present in the native app's main Library from mirrors introduced only for LiveContainer. Remove only those introduced mirrors from native staging after copying the latest guest values into their group staging area. This prevents stale main-home duplicates from conflicting with the actual shared preferences on a subsequent export. Regression coverage includes restore followed by export again.

Folder attachment and the pre-offload recheck now require the complete expected group list, so an older main-files-only backup cannot authorize deleting a grouped native app. The wizard explicitly directs the user to enable Isolate App Group for the selected LiveContainer container, close related apps using the same shared data, verify saves/settings, and keep backups. SideKick does not edit LiveContainer's private settings or assert that sharing an IPA proves successful execution.

## Verification and limitations

New core regressions cover group entitlement mapping/ambiguity, app/group round-trip, mapped shared preferences and deletions, preserved OS metadata, missing groups, symlink and traversal rejection, and no main-home replacement on failed group preflight. Existing main-files-only round-trip tests remain. The isolated vendor-composition fixture verifies the helper receives source group metadata and requested entitlements rather than an empty array. Local Python fixtures passed; Swift behavioral cases and the full iOS build require macOS CI and are not yet observed. No build monitoring or release publishing was performed, per the user's instructions.

Device validation still required: create/import the Spotify IPA; verify the helper's actual provisioned group access; export and select the folder; enable container isolation; verify app data and suite preferences; only then test offload and restoration. Shared apps/extensions can mutate group files concurrently, and preference-daemon caching/signing behavior must be checked on device. App Group support is implemented, not claimed device-verified. Keychain logins are not transferred.

Graphify was consulted before source reads and refreshed after edits. Architectural boundary: root transfer engine is compiled into both SideKick and SideBackup by `scripts/embed-file-transfer.py`; helper entitlement requests belong in staging, actual permissions in the signed helper, and LiveContainer owns guest isolation. The raw vendor graph is not the composed shipping source. Changes stay on main, preserving unrelated VPN/vendor/audit/graph work; no subagents were used.
