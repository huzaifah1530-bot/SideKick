# Offload helper identity and console

The device reported `App Group is not configured` while Spotify was temporarily replaced by SideBackup. The composed SideKick bundle extension derives its self identity from the running bundle. Inside the renamed helper that is Spotify, so the helper searched for a Spotify-derived store group instead of SideKick's shared backup group. Provisioning also unconditionally appended a team suffix in Release, which could change an already signed store group.

`scripts/integrate-backup-helper.py` applies after the audited patches without editing the dirty vendor checkout. Staging records the actual signed host group in helper metadata and requests that group. Provisioning preserves it exactly only when it belongs to the running host and the selected team is the host's signing team. The bundle resolver accepts the metadata only when the helper's actual executable entitlements contain the exact group; there is no substring/suffix fallback for marked helpers. Signing checks this before helper installation, so missing permissions fail before replacing the native app. The backup engine, backup paths and restore semantics remain unchanged.

The purple ContentView is replaced at composition time with SideKick's dark system background, blue accent, status heading, real byte progress and bounded activity log. Boot and operation errors appear in that screen. Main-app offload/recovery starts on a dedicated console using the existing OperationStatusView. Its activity log is open initially. The existing pipeline progress object supplies percentages, and filtered pipeline-step notifications supply human-readable stage messages. No timer manufactures progress. Observers are removed/invalidated on completion; run IDs ignore late UI callbacks after retries. Retry recovers an interrupted native operation before another offload. The optional LiveContainer offer appears after a successful console result and an inactive native record, when the console is closed.

Logs are in-memory UI messages, with bounded counts. Pipeline notifications carry only app identity and stage, never credentials, provisioning payloads or network response data. Raw engine log files are not copied into the UI.

Portable checks verify clean pinned-vendor patch composition, metadata routing, provisioning branch ordering, pre-install entitlement validation, helper branding, console wiring and actual backup-before-uninstall ordering. On macOS the fixture also parses the composed Swift files and executes the actual bundle resolver against differing store/helper identities, a doubled team suffix, absent grants and the ordinary unmarked-bundle fallback. Windows has no Swift compiler, so those compiler/runtime checks require CI. Physical-device backup, offload, restore and callback behavior remain to be tested. No build monitoring or release publication was performed.
