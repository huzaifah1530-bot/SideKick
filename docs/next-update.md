## Completed

### Anisette server refresh and recovery

- The setting is renamed to **Use Newest Anisette Server**. Tapping it downloads `config/anisette-servers.json` from the repository's default branch (`raw.githubusercontent.com/.../HEAD/...`, not Releases), checks it, and applies the recommended server URL and headers through the existing gated Anisette save path.
- A **Newest Server** section on the same page shows the recommended server, when the list was last updated (the file's last commit date, falling back to its `updatedAt` field) and when the user last switched.
- Sign-in, refresh, install and scheduled-refresh failures caused by Anisette now point to that setting. The add-account alert has an **Anisette Settings** button.
- Format and maintenance steps: `config/README.md`. Only `X-Mme-Client-Info` and `User-Agent` can be sent. SideKick's Anisette request path has no generic header support, so a list asking for any other header is rejected instead of being half-applied.
- The file must be on the default branch (`main`) before users can fetch it.

### Support multiple LiveContainer installations and shared apps

- The folder setup now asks for the folder type (**Private apps** or **Shared apps**) and the installation (LiveContainer, LiveContainer 2, LiveContainer 3 or a custom scheme). It also names connections to match.
- All guests from every folder stay in the one **LiveContainer** section on Home. Shared guests are captioned "Shared app".
- Linking the same folder twice is rejected, so a shared folder reached from two installations isn't listed twice.
- `livecontainer3` has been added to the URL query schemes, the certificate callback allow-list and the LiveContainer bundle ID check.
- Shared apps are now found automatically. SideKick requests LiveContainer's App Group (`group.com.SideStore.SideStore`, team suffix added at signing) and reads `LiveContainer/Applications` there. This needs SideKick and LiveContainer signed with the same Apple ID, and SideKick refreshed once after updating.
- Shared apps open in the LiveContainer already running them, otherwise the first installed one in LiveContainer's own launch order. Updates for any LiveContainer app go straight to LiveContainer 1 (`livecontainer://install`), the only installation that can install or replace apps.
- LiveContainer 2 and 3 only run shared apps, so their own folders are normally empty; the folder setup screen now says so.

### Fix the LiveContainer update controls and confirmation sheet

- Download / Send to LiveContainer / Re-download / Delete IPA now sit inline on the page instead of in a floating bottom bar.
- The "Did the Update Install?" sheet opens fully expanded.

### Make LiveContainer app pages match regular app pages

- Same layout as the regular app page: header with **Open**, inline Update section, GitHub Updates link with the regular footer, then Details.
- LiveContainer-only actions are in the ••• menu: Check for Updates, Installed Build, I've Installed / Skip, Open LiveContainer, View on GitHub, Manage Folder, Copy Bundle ID and Remove.

### App icon follows the accent colour

- When the accent changes, the app icon switches to the precompiled variant centred on the accent's hue (15° steps, plus a grey icon for unsaturated accents). Fixed: red accents gave an orange icon because variants matched only the gradient's top-left colour, and SideKick's own row on Home showed a grey placeholder after a change. The default teal keeps the original icon. A **Match App Icon to Accent** toggle and a preview are in Settings → Appearance.
- Running inside LiveContainer, iOS's icon belongs to LiveContainer. SideKick instead replaces the icon LiveContainer caches in SideKick's guest bundle (`LCAppIconLight.png` / `LCAppIconDark.png`) and clears its cached tile colour. LiveContainer shows the new icon the next time it reloads its app list.
- Variants are generated by `scripts/generate-tinted-icons.py`. CI checks that they are registered as alternate icons.
